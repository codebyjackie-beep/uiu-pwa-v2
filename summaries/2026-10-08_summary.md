# 2026-10-08 — Cook mode resume bug fix (blank screen on reopen)

Handoff: `CC prompt：Cook mode 再開變空白（resume bug）— 即修`。Jackie 真手機報告：剔咗
"Mark as done" → 閂 app → 再開同一條 recipe 嘅 cook mode → 成版空白，永遠卡住。

## Root cause（已確認）

`apps/web/app/recipes/[id]/cook/CookMode.tsx` 嘅 mount `useEffect`：

- 有 saved progress 時淨係 `setSavedProgress(saved)`，**冇改 `resumeChoice`**，佢一直停喺
  `"pending"`。
- Render 次序係 `if (resumeChoice === "pending") return <loading div>` 喺
  `if (savedProgress)` **之前** → resume prompt 永遠 render 唔到，卡死喺空白 loading div。
- 後果：任何有 saved progress（`done.length > 0` 或之前淨撳過 Next）嘅 recipe，之後每次入
  cook mode 都空白，直到 localStorage 清咗為止。

## Fix（commit `506ea50`）

`apps/web/app/recipes/[id]/cook/CookMode.tsx`：

1. `resumeChoice` 改做三態 `"pending" | "prompt" | "resolved"`。
2. 抽咗一個 **純 function** `initialCookState(saved, stepCount)`（同檔案 export），
   由 saved progress + 現時 step count 決定 `{ resumeChoice, savedProgress }`：
   - 冇 saved / `stepCount <= 0` / `saved.current >= stepCount` → `resolved` + `null`
     （唔信任過期/超出範圍嘅 `current`，寧願當冇進度，由頭開始）。
   - 否則 clamp `current` 落 `[0, stepCount-1]`，`done` 剔走 `< 0` 或 `>= stepCount`
     嘅 index。
   - **Resume 條件擴闊：** `done.length > 0 || saved.current > 0`（原本淨係睇
     `done.length > 0`，而家淨撳 Next 冇剔都會觸發 resume prompt）。
   - 冇嘢好 resume → `resolved` + `null`；有 → `prompt` + clamp 咗嘅 `{current, done}`。
3. Mount effect改做：

   ```ts
   const saved = loadProgress(recipeId);
   const initial = initialCookState(saved, steps.length);
   setSavedProgress(initial.savedProgress);
   setResumeChoice(initial.resumeChoice);
   ```

   兩個分支都會set `resumeChoice`，唔會再卡喺 `"pending"`。
4. Render 改做 `if (resumeChoice === "prompt" && savedProgress)` 先顯示 resume card，
   `pending`/`resolved` 行為不變；`continueFromSaved`/`startOver` 依舊set `"resolved"`。
5. **冇郁** timer / wake lock / speech / ingredients 邏輯——淨係呢個 state machine。
